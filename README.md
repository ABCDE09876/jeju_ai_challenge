# 제주의 두 얼굴 (Jeju True-Life & Citizen Lawyer Agent)

「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」(제주테크노파크, DAKER) 출품작입니다. 관광객·기상·평균이라는 3대 허수를 걷어내 도민 기준의 결론을 내고, 통계 주장·기사·민원 문장을 데이터로 감사합니다.

> **데이터 고지**: 분석 테이블은 공식 예시데이터의 컬럼명·코드값을 따르는 **시드 고정 합성(시연용) 데이터**입니다. 화면의 결론은 실제 제주 현황이 아니라 분석 절차의 시연입니다. 원자료 CSV 를 `data/raw/` 에 넣으면 같은 절차로 다시 계산합니다(12장).

관련 문서: `docs/실행_매뉴얼.md` (화면 사용법·문제 해결), `docs/데이터_활용_명세서.md` (데이터 출처·전처리·합성 상세), `docs/AI_Agent_기획서_15쪽_완성본.md` 와 `docs/AI_Agent_기획서_15쪽.html`·`.pdf`·`.pptx` (기획서).

## 3. 환경변수(.env)

`.env.example` 을 `.env` 로 복사(`Copy-Item .env.example .env` 또는 `cp .env.example .env`)한 뒤 값을 넣습니다.

| 변수 | 설명 |
|---|---|
| `ANTHROPIC_API_KEY` | 선택. 비우면 100% 로컬 모드(외부 호출 0회), 넣으면 하이브리드 모드 |
| `ANTHROPIC_MODEL` | 참고용. `claude-opus-5-5` 고정이라 다른 값은 무시(사이드바에 무시 사실 표시) |
| `JEJU_DATAHUB_API_KEY` | 선택. 원자료 내려받기용 보관 자리이며 이 값을 읽는 코드는 없음(5장) |

키 우선순위는 사이드바 `Anthropic API Key (선택)` 입력 > 시스템 환경변수 > `.env` 입니다. `.env` 는 UTF-8 과 CP949(메모장 ANSI) 저장을 모두 읽고, 제출 ZIP 기본 모드에서 빠집니다. 키는 소스·문서에 적지 않습니다(`scripts/audit_codebase.py` 가 검사).

## 4. Claude 사용 정책(고정값)

`src/config.py` 에 고정하고, 모든 요청이 `src/agent/claude_bridge.py` 의 `ClaudeBridge.build_request()` 한 곳을 지납니다.

| 항목 | 값 |
|---|---|
| 모델·추론 | `claude-opus-5-5`, `output_config.effort = "xhigh"`, thinking `{"type": "adaptive", "display": "summarized"}` |
| `max_tokens` | `128000`. Messages API 필수 항목이라 모델 최대 출력값을 넣음(응답을 줄이는 값 아님) |
| `temperature` | 보내지 않음(Opus 5.5 미지원) |
| 비용 상한 | 없음: 호출 횟수 제한, 일일 상한, 토큰 축소, 저가 모델 대체, 다른 모델 서버측 폴백 모두 없음 |
| 시간 기준 | 첫 스트림 이벤트가 3.5초 안에 없으면 로컬 전환(연결 타임아웃도 3.5초), 600초 무이벤트면 끊긴 연결, SDK 재시도 0회 |
| Tool Use | 스트리밍 + 수동 루프: `stop_reason` 이 `tool_use`(또는 `pause_turn`)인 동안 모든 `tool_use` 를 로컬 도구로 실행해 `tool_result` 목록을 한 번에 반환. `eager_input_streaming: true`, 입력은 클라이언트에서 스키마 검증 |
| 이력·캐시 | 대화 이력 append-only. 캐시로 Claude 호출을 건너뛰지 않고, 이전 Claude 해설은 장애 순간에만 대체 표시. 화면이 다시 그려지면 백그라운드 스트림 취소 |

- **로컬 자동 전환**: 키 없음, 강제 로컬 모드, 인증·권한 오류, 모델 접근 불가, 429, 네트워크 오류, 3.5초 내 첫 응답 없음, 스트림 중단, 서버 오류, 요청 형식 오류, 거절(refusal), 출력 한도 도달, SDK 미설치, 빈 응답. 어느 경우든 화면 오류 없이 같은 질문을 로컬 엔진이 답합니다.
- **외부 전송과 비용**: 키가 있으면 시스템 프롬프트, 질문, 로컬 파서 힌트, 도구 결과 요약, 같은 탭의 이전 대화가 Anthropic API 로 전송됩니다. 코드에 비용 상한이 없으므로 평가용 키는 Anthropic Console 에서 사용 한도를 걸고 평가 후 폐기하기를 권장합니다(대회 규정 권고).
- **실측** (`fuzz_report.json` 의 `live_cases`, 2026-11-18 재실행. 그 뒤의 해석기 사후 수정 3판·4판은 이 5문항의 질문 해석을 바꾸지 않음): 실제 API 5문항 5 / 5 통과, 5건 모두 Claude 경로로 완료. 응답 시간 최소 10.6초·최대 46.1초, 도구 호출 0회에서 4회, 해설 속 숫자 98개가 모두 도구 결과와 일치. 11-17 실행에서는 89개 중 1개(전기차 문항의 '95')가 도구 결과에 없는 숫자라 수치 근거 감사기가 '근거 없음'으로 표시했습니다(화면 배지 19 / 20). 이전 실행에서는 최대 60.8초가 걸린 적이 있고, SQL 주입 문자열에 Claude 가 응답을 거절해 로컬로 자동 전환된 적도 있습니다(9-3). 문항을 40개로 늘린 실제 연결 시험은 9-10 에 있습니다.

## 5. 제주데이터허브 API Key 발급·설정

기본 데이터 경로는 오프라인 로컬 DB·CSV 이므로 앱 실행에는 필요 없습니다. 원자료를 직접 받을 때만 씁니다.

1. 제주데이터허브 누리집(jejudatahub.net)에 회원가입하고 로그인합니다.
2. 필요한 데이터셋 페이지에서 API 활용을 신청합니다. 대응 목록 번호: #753 유동인구, #725·#1249 버스 이용, #727 노선, #726 정류소, #756·#757 기상, #515 음식물 쓰레기, #749·#742 와이파이, #136 전기차 충전.
3. 마이페이지 또는 API 관리 메뉴에서 발급된 인증키를 확인합니다. 메뉴 이름과 절차는 누리집 개편에 따라 다를 수 있습니다.
4. 키는 `.env` 의 `JEJU_DATAHUB_API_KEY=` 뒤에만 적습니다.

현재 코드는 데이터허브 API 를 호출하지 않고 이 값을 읽지도 않습니다. 받은 원자료는 CSV 로 `data/raw/` 에 넣습니다(12장). 대회 규정상 데이터 API Key 는 제출하지 않으며, 패키징 스크립트가 모든 모드에서 이 값을 비웁니다.

## 7. 에이전트 구조

```

     -> [5] 스트리밍 해설, 3단 대시보드, 1페이지 증거 카드(HTML), 후속 질문 버튼 3개
```

- 2차(사후, 고친 코드로 같은 40문항): 기준표 34 / 40, 판정 40 / 40 이 로컬 엔진과 같음, 벤치마크 23 / 24(로컬과 같음, D2 해결), 해설 숫자 878 / 881, Claude 모드 38 / 40(2문항은 첫 응답 지연으로 로컬 자동 전환), 답변 시간 중앙값 34.6초. 남은 근거 없음 가운데 2개('38.6% 적습니다'처럼 감소를 양수로 쓴 값)는 감사기가 도구 쪽 음수를 크기로 비교하지 않아 생긴 표시라 고쳤고(사후), 2차 답변을 기록된 도구 호출로 재연하면(API 호출 없음) Claude 답변 38개의 해설 숫자 852 / 852 가 근거와 일치하고 기준표는 37 / 40 입니다.

## 12. 데이터 정직성 고지와 원자료 적재

- 대회 제공 파일은 원본 그대로 적재했습니다(예시데이터 70개 시트 -> `bdc_<시트코드>`, 데이터목록 1,259건 -> `datahub_catalog`). 분석 테이블은 공식 시트의 컬럼명·코드값을 쓰는 **공식 스키마 보존, 시드 고정(SEED=20261120) 합성 확장 데이터**입니다. 예시 시트가 시트당 1행뿐이라 예시값은 규모 기준점으로만 쓰고, 생성 분포는 `column_profile` 에 공개했습니다.
- `table_registry` 91개 테이블 1,090,386행 중 합성·보정 표본(`synthetic_seed`, `calibrated_reference`)이 1,088,562행(99.8%)이고 원자료(`official_raw`) 적재는 0건입니다. 생활 주제의 합성 기간은 2026-05-01 ~ 2026-10-31 이며, 모든 분석 행에 `source_type`·`dataset_id`·`reference_date` 출처 태그가 붙습니다.
- 검증용으로 버스 정류소 6곳에 혼잡 구간을 심었고(H1부터 H6까지, 설계 배율 1.6배에서 3.2배) 분석 도구는 이 설정을 읽지 않습니다. 사용자 제공 공개 통계 사례 4건은 `reference_cases` 에 기록했고, 한림읍 음식물쓰레기(2019-10 일평균 1,045.23 -> 2019-12 61,346.42, 58.69배)와 전기차 충전(2,447행 중 시각 유효 113행) 표본은 그 수치에 맞춰 보정했습니다.

## 14. 한계

1. **데이터·벤치마크**: 결론은 합성 데이터 위의 절차 시연이고, 원자료 경로는 실데이터로 검증하지 않았습니다. 벤치마크는 24문항이며 정답이 합성 설계값이라 실세계 정확도를 뜻하지 않습니다. T10 유형(주말 감소와 상쇄된 토요일 혼잡)은 미탐입니다.
2. **퍼징**: 형식 검사이며 정답 채점이 아닙니다(예: 영어만 쓴 F27 은 `insufficient_area` 로 답하고 통과).
3. **수치 근거 대조**: 휴리스틱입니다. 날짜(년·월·일) 숫자, 0에서 24 사이 정수 시각, 곳·회·개 같은 개수 단위 정수, 소수점 없는 0·1·2·3 은 검사하지 않고 반올림 오차(값의 0.5% 또는 0.051 중 큰 값)를 허용합니다. Claude 에게 도구 결과의 숫자만 인용하라고 지시하지만, 실제 연결 시험에서 도구 결과에 없는 숫자 1개가 해설에 나온 적이 있습니다(4장 실측, 감사기가 표시).
4. **데이터 구조**: 강수량은 일 단위, 시간대별 배차는 합성값, 차내 혼잡 없음, 카드는 월 단위, 유동인구는 치안·소음 같은 생활 품질을 측정하지 않습니다.
5. **판정 보류·지역**: 부동산 가격, 소음, 치안, 학군, 대기질, 주차, 주관적 만족도와 보유 기간 밖 시점은 판정을 보류합니다. 지역은 제주 43개 읍면동과 별칭만 인식합니다.
6. **시각 해석**: 오전·저녁 단서 없는 "8시"는 질문 주제(앞 대화에서 이어받은 주제 포함)가 퇴근·야간·생활이면 20시, 혼잡·소비 같은 그 밖의 주제면 오전 8시로 해석합니다(예: 장날 혼잡 질문 뒤의 "그럼 8시 이후는?"은 오전 8시). "저녁 8시 이후"처럼 적으면 확실합니다.
7. **Claude 경로**: 응답에 10초 이상 걸리고(실제 연결 40문항 중앙값 36.0초, 최대 65.3초) 비용 상한이 없으며 질문이 외부로 전송됩니다. 상단 배지는 키 유무만 보므로 실제 엔진은 분석 진행 표시에서 확인합니다.
8. **환경**: Windows 11 + Python 3.13.9(개발 PC)·3.12.10(별도 PC 새 가상환경)에서만 실행 검증했고 센터 PC 실기·Linux·macOS 기록은 없습니다. 로그인이 없는 단일 사용자 시연 앱이며 대화 기록은 새로고침하면 사라집니다.
9. **말투 견고성**: 평가용 세트 1차 84.0%(현재 사후 87.3%). 문장 전체를 영어로 쓰고 지명을 로마자로 쓴 질문, 단서어 자체의 오타('엉제', '쥬말', '학셍'), 조건을 빼고 줄인 초단문('8시 버스'처럼 오전·오후가 없는 시각)은 잘못 해석될 수 있습니다. 시험 질문은 템플릿 364문항과 그 LLM 변형이라 실제 사용자 질문 분포와 다를 수 있습니다.
10. **대규모 조합 시험**: 2,550만 문항은 문장틀 17,927개에 값과 입력 변형을 조합한 질문이라 모두가 서로 독립된 실제 질문은 아닙니다. 평가용 공식 86.4% 의 남은 오답은 단서어 오타, 해석기가 모르는 낱말('연세 드신 분', '애들'), 생성 모델이 뜻을 바꾼 틀이며, 틀의 뜻이 바뀐 경우(라벨 잡음)도 오답으로 세므로 실제 해석 정확도보다 낮게 나올 수 있습니다. 두 글자 지명의 오타('누형', '애웟')는 다른 실제 낱말과 겹칠 위험이 커서 일부러 넓게 받아들이지 않았습니다.
11. **다양성 대규모 시험**: 7,100만 문항도 문장틀 60,933개에 값·말투·상황·입력 변형을 조합한 합성 질문이라 모두가 서로 독립된 실제 질문은 아닙니다. 평가용 공식 93.0% 의 남은 오답은 단서어 자체의 오타, 평가용에만 넣은 낯선 표현('구름 한 점 없는 날', '인산인해'), 지명 속 띄어쓰기('삼 양동', 이 변형만 66.1%), 두 글자 지명의 오타이며, 뜻이 바뀐 틀(라벨 잡음)도 오답으로 셉니다. 평가용 값도 개발용과 같은 방식으로 만들었고 해석기 수정 기간에 저장소에 있었으므로(검토 에이전트에게는 열지 못하게 함) 완전히 눈을 가린 시험은 아닙니다.
12. **1억 문항 확장 시험**: 문장틀은 9-7 과 같고 새 값·새 입력 변형·새 앞 질문 표현만 더했으므로, 새 LLM 문장틀로 만든 질문보다 낯선 정도가 작습니다. 평가용 공식 92.3%(새 요소 문항 89.3%)의 남은 오답은 평가용에만 넣은 낯선 표현('우천 걱정 없는 날', '토요일캉 일요일', '교육 경쟁력')과 단서어 자체의 오타이며, 라벨 잡음(문장틀 자체가 자료 목록을 묻는데 앞 질문을 잇는 질문으로 라벨이 붙은 틀 등)도 오답으로 셉니다. 공식 채점 뒤 되돌린 회귀 4가지(사후 수정)를 넣은 제출 코드의 점수는 평가용 오답을 본 뒤의 사후 점수입니다. 사후 수정의 '붐비는 시기' 허용 목록은 뒤 말의 오타('시기느'·'시기앗나여' 등)를 놓쳐 공식 채점 해석기보다 5문항(개발용 3·평가용 2)을 새로 틀렸고, 이것은 고치지 않았습니다. 모음 혼동 오타는 단서어 17개에서만 바로잡습니다.
13. **6천만 문항 새 말투 시험**: 문장틀 글은 새로 만들었지만 질문 유형 57종과 끼울 값은 이전 시험과 같아, 유형이나 값까지 새로운 질문보다 낯선 정도가 작습니다. 평가용 공식 92.7% 의 남은 오답은 단서 낱말을 이모지로 바꾼 문장(이 변형만 37.1%, 해석기가 이모지를 지워 단서가 사라짐), 평가용 값 중 해석기가 모르는 표현('빗방울 똑똑 떨어지는 날'·'도난 사고'), 단서어 자체의 오타('시가대'·'디다릴')이며, 라벨 잡음('~것이 사실입니까?'를 일반 질문으로 라벨한 틀 등)도 오답으로 셉니다. 평가용 전용 변형 5종의 정의와 말투·상황 목록은 해석기 수정 기간에 저장소에 있었으므로 완전히 눈을 가린 시험은 아닙니다. 공식 채점 뒤 회귀를 막은 사후 수정 코드의 점수는 사후 점수이며, 한글에 붙은 영어 낱말('workfor아동') 2문항, 오타가 만든 단서어 2문항, '덜'의 오타('더 사람이 많은 시간대') 5문항, 이전 시험에서 찾은 회귀 중 오타 꼴 164문항('좀'의 오타 '점'이 이어진 '점심' 등)은 고치지 않았습니다.

## 16. 화면 상태 표시 문구 (코드 원문)

`src/agent/orchestrator.py` 의 문구를 그대로 옮깁니다. 배지 상수는 두 개이고, 세 번째는 질문 처리 중 자동 전환 때 분석 진행 표시에 나오는 문구입니다.

1) 하이브리드 모드 배지(`HYBRID_BADGE`, 키가 있고 강제 오프라인이 꺼져 있을 때):

```
🟣 하이브리드 부스터 모드 가동 중 (Anthropic Claude API 추론 + 로컬 정밀 연산 | 오프라인 자동 폴백 대기)
```

2) 로컬 모드 배지(`LOCAL_BADGE`, 키가 없거나 강제 오프라인을 켰을 때):

```
🟢 100% 로컬 온프레미스 자립 모드 가동 중 (외부 API 비용 0원 | 센터 PC 완벽 호환)
```

3) 자동 전환 문구(`{사유}` 에 4장의 전환 사유가 들어감, 예: `API Key 인증 실패 -> 로컬 엔진 자동 전환`):

```
{사유} -> 로컬 엔진 자동 전환
```

배지는 화면 표시용 원문이며, "센터 PC 완벽 호환"의 근거는 6장 측정값입니다(센터 PC 실기 측정 없음).
