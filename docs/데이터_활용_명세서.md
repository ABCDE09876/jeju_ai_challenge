## 4. 공간 키와 43개 읍면동 별칭 사전

근거: `data/meta/jeju_gazetteer.json`(version 2026-11-16, `scripts/build_gazetteer.py`). 프로젝트가 정리한 사전이며 공식 확인 여부를 상태 필드로 구분합니다.

- 구성: 읍면동 43개(제주시 26, 서귀포시 17 / 동 31, 읍 7, 면 5), 권역 7개, 법정동 연결 78행(이름 73종), 별칭 48개(대상별로 펼치면 70행), 랜드마크 16곳, 정류소 24곳, 관측소 5곳.
- code_status: official_example 2(한림읍 50110250은 4-10·4-11·4-13·4-14·4-15 예시, 일도1동 50110510은 4-12 예시), standard_pattern 41(행정기관코드 체계 패턴으로 부여, 원자료 적재 시 재확인).
- coord_status: 정류소 1(국제여객선터미널)과 관측소 328(중문)만 official_example, 나머지(읍면동·랜드마크 전부, 정류소 23, 관측소 4)는 반경 계산·시각화용 approximate.
- mapping_confidence: high 32, review 11(법정동-행정동 관할 재확인 필요). id_status(정류소): official_example 2(ID 1, 96), synthetic 22(9001~9022, 실제 ID 아님).
- 지명 해석(`gazetteer_index.py`): 자모 편집거리 유사도 85% + 자모 2-gram 자카드 15%로 4자 이상 0.75, 3자 이하 0.80 이상이면 교정. 초성(3자 이상), 조사 분리, '일동' -> '1동' 변환, 2어절 별칭 우선.
- 결합(`catalog_resolver.describe_unit`): 읍면동 -> 법정동 -> 정류소(같은 읍면동 소속이거나 중심에서 도시 동 1.5km, 읍·면 4.0km 이내, 최대 6곳) -> 최근접 관측소(하버사인 거리). 지역이 1곳이면 사전의 비교 힌트로 비교 상대를 붙입니다.

### 6.2 자가 치유 로더(`src/tools/resilient_loader.py`)

인코딩(utf-8-sig -> cp949 -> euc-kr -> utf-8 -> latin1)과 구분자(쉼표, 탭, 세미콜론, 파이프)를 자동 판별하고, 열 개수가 맞지 않는 행은 건너뛰어 개수를 보고하며, 빈·중복 머리글에 이름을 붙입니다. 빈 파일·헤더만·바이너리도 예외 없이 결과 객체와 안내 문장으로 돌려줍니다. 0으로 나누기·NaN은 None으로 흡수해 화면에 '산출 불가'로 표시합니다.

## 7. 분석 흐름: 3대 교란 박리와 보조 감사

### 7.1 인메모리 큐브(`analysis_cubes.py`)

- 유동인구(읍면동 x 일 x 시간): resident = resd '제주' 행의 resd_pop_cnt + work_pop_cnt + visit_pop_cnt, outsider = resd '그외' 행의 같은 합, total = resident + outsider.
- 버스(정류소 x 일 x 시간): 승차, 하차, 어르신 승차, 청소년 승차, volume = 승차 + 하차.
- 카드(읍면동 x 월 x 도민 여부 x 시간대): 법정동(bjd)을 4.4절 3번 규칙으로 행정동에 배분한 이용금액. 도민 비중·도민 야간(21~24시, 00~06시) 비중 계산에 씁니다.
- 공통 플래그: market_days 달력(요일, 주말, 장날, 7~8월 성수기)과 최근접 관측소 우천 여부. DB 수정 시각이 바뀌면 다시 읽습니다.

### 7.2 단계별 박리(Tool 2 `decompose_confounders`)

| 단계 | 정의 |
|---|---|
| S0 단순 평균 | 지역의 시간당 평균 total(관광객 포함, 24시간, 날씨 무관) |
| S1 ① 관광객 거품 제거 | 시간당 평균 resident. 도외 거주자 비중 = outsider 합 / total 합 |
| S2 ② 생활 시간대 | 요청 시간대·요일의 도민 평균. 지정이 없으면 주제별 기본값(퇴근 17~19시, 야간 21~23시, 생활·일반 18~22시, 혼잡 8~20시, 소비 18~21시) |
| S3 ③ 악천후 | S2 조건 + 비 오는 날. 날씨를 말하지 않으면 비 오는 날을 스트레스 테스트로 적용 |
| 야간 공동화 | 야간 잔류율 = 도민 21~23시 평균 / 12~17시 평균 |
| 날씨 파급 | 비 오는 날과 안 오는 날의 도민 체류 변화율, 인근 정류소 평일 같은 시간대 일 승차 합 변화율 |
| 소비 보조 | 카드 이용액 중 도민 비중, 도민 이용액 중 21~24시와 00~06시 구간 비중 |

- 우천일: 최근접 관측소 일 강수량 1.0mm 이상(`config.RAIN_DAY_MM`). 여러 읍면동으로 된 별칭은 소속 읍면동의 시간당 평균으로 비교합니다.
- 판정: S0 1위와 최종 단계(날씨를 지정하면 S3, 아니면 S2) 1위가 다르면 reversal, 최종 1위는 같지만 S3 1위가 다르면 conditional_reversal, 그 밖에는 no_reversal, 비교 지역이 2곳 미만이면 insufficient_area.
- 완화 사다리(`relax_by_ladder`): 요청 조건 -> 인접 시간대(앞뒤 1시간)·평일/주말 구간 -> 지역 전체. 서로 다른 일자가 5일 미만이거나 값 합이 0이면 다음 단계로 넓히고 "요청하신 세부 조건(N=...일<5)의 표본이 적어 ... 자동 확장" 문장을 한계 구획에 남깁니다.

### 7.3 Tool 3 `excavate_masked_slice`의 감사 규칙

- 은폐 구간: 질문 지역 정류소(없으면 가까운 2곳, 최대 4곳)의 승하차(어르신·청소년 질문이면 해당 승차)와 지역 체류 인구를 요일군 14개(장날, 비 오는 평일·주말, 7~8월 주말, 비 오는 날, 평일, 주말, 월~일요일)로 나눕니다. 해당 일수가 5일 이상이고 전체의 45% 이하인 요일군에서 같은 시각 전체 기간 평균의 1.3배 이상이면서 같은 시각 평균이 5 이상인 연속 시간대를 채택합니다. 12시간 이상 이어지면 '하루 종일(05~23시)'처럼 표기합니다.
- 집계 단절: 월별 로그 차분에서 월간 배율 2.0 이상·0.6 이하, 또는 로버스트 z(중앙값·MAD x 1.4826) 4 이상이면서 배율 1.5 이상·0.67 이하인 달을 후보로, 전후 3개월 평균 비가 1.8 이상·0.65 이하이면 확정합니다. 확정된 단절은 `aggregation_changes`와 대조해 "집계변경 이력 일치" 또는 "이력 없음: 현장 확인 필요"로 설명합니다. 주장 속 'N배'는 가장 가까운 계산값과 5% 이내면 '수치 일치'입니다.
- 인과 감사: 인과 표지어(때문, 탓, 원인, 로 인해 등 14개), 원인 개념 13종(관광객, 전기차, 비, 기온, 소득·경기, 이주, 공사, 축제·행사, 감염병, 집계·수집 방식, 주차, 고령화, 장날), 결과 개념 6종(음식물쓰레기, 전기차 충전 대기, 와이파이, 버스, 카드 매출, 유동인구)이 모두 있으면 감사합니다. 결과 테이블에 그 개념의 측정 컬럼이 `column_registry.concepts`로 등록돼 있거나 원인 후보 테이블과 기간·시간 단위가 맞으면 '연관 검정 가능(인과 미검증)', 아니면 '미측정 원인'으로 보고 중립 교정문을 만듭니다(예: 음식물쓰레기 2018-01~2021-05와 관광객 후보 2026-05~10은 기간이 겹치지 않음, 월 단위 카드 매출과 일 단위 비는 시간 단위가 다름).
- 분모 감사: 전기차 기록의 전체 행, 미충전 행, 대기시간 계산 가능 행(요청·시작 시각 유효, 시작이 요청 이후, 충전량 0 초과)의 비율이 30% 미만이면 분모 함정입니다. 현재 표본은 2,447행 중 미충전 154행, 계산 가능 113행(4.6%), 그 113행의 평균 대기 18.5분·중앙값 16.0분입니다.

### 7.4 역전 경계(Tool 4 `simulate_reversal_boundary`)

귀가 불편 지수(분) = 60 / (2 x 시간당 정차 버스 수) + max(0, 버스 1대당 승하차 - 10) x 0.25. 귀가 시각(17~23시), 방문 시각(8~20시, 최대 혼잡의 60% 이하로 떨어지는 첫 시각), 허용 대기(3~30분), 비 여부를 움직여 유불리가 바뀌는 시각을 찾습니다. 버스 수는 합성 배차표 값입니다.

### 8.5 원자료로 교체하는 방법과 제약

1. 원자료 CSV를 `data/raw/`(없으면 만듦)에 넣고 `python scripts/build_jeju_db.py`를 실행합니다(항상 새로 구축).
2. `read_raw_tables`가 파일명 순으로 자가 치유 로더로 읽어 아래 필수 컬럼을 모두 가진 첫 파일을 해당 테이블로 채택합니다. 채택 테이블은 source_type `official_raw`, reference_date는 적재일이 되고 build_log `raw_tables`에 파일명이 남습니다. 응답 캐시 키에 DB 수정 시각이 들어가 예전 답변은 재사용되지 않습니다.

| 테이블 | 필수 컬럼 |
|---|---|
| floating_pop_hourly | base_date, time, emd_nm, resd_pop_cnt, work_pop_cnt, visit_pop_cnt |
| bus_stop_hourly | base_date, base_hour, bus_station_id, get_on_off_type, user_count |
| card_time_monthly / card_week_monthly | base_year_month, bjd, user_type, time(요일별은 week), use_amt |
| weather_daily | base_date, observatory_code, daily_rainfall |
| food_waste_monthly | base_year_month, emd_nm, discharge_daily_avg |
| wifi_monthly_users | base_year_month, visit_type, user_count |
| ev_charging_wait | charger_id, start_time, charge_kwh |

3. 현재 코드의 제약: 요일·장날 달력은 `config.py`의 ANALYSIS_START~ANALYSIS_END(20260501~20261031)로 만들므로 원자료 기간에 맞춰 바꿔 재구축해야 합니다(바꾸지 않으면 달력 밖 일자의 주말·장날 플래그가 False). 날짜 키는 YYYYMMDD 문자열이어야 하고, 판정 보류 보유 기간(`intent_parser.TABLE_COVERAGE`)과 인과 감사 테이블 기간(`slice_excavator.TABLE_GRAIN`)도 함께 바꿔야 합니다. 정류소 사전은 교체되지 않아 실제 ID가 사전에 없는 정류소는 분석에서 빠지고 관측소는 기본값 184로 붙습니다. 마스킹 셀은 합산 때 0, 성·연령별 행은 합산만 합니다. 심어 둔 시나리오와 보정 사례는 교체된 테이블에서 사라지며 24문항 벤치마크 정답은 원자료 DB에 그대로 적용할 수 없습니다.

## 10. AI 모델 사용과 외부 서비스 의존성, 오프라인 폴백 명세

### 10.1 Claude 고정 정책(`src/config.py`, `src/agent/claude_bridge.py`)

| 항목 | 값 |
|---|---|
| 모델·추론 | claude-opus-5-5 고정, `output_config.effort` = "xhigh", thinking `{"type": "adaptive", "display": "summarized"}`. 모든 요청은 `build_request` 한 곳에서 만들고 환경변수 ANTHROPIC_MODEL은 무시(다른 값이면 사이드바에 표시) |
| max_tokens·샘플링 | 128000(API 필수 항목이라 모델 최대 출력값). temperature 등은 보내지 않음(Opus 5.5 미지원) |
| 비용 상한 | 없음: 호출 횟수 제한, 일일 상한, 토큰 축소, 저가 모델 대체, 서버측 다른 모델 폴백을 쓰지 않음 |
| 도구 연동 | 4개 도구 JSON Schema(`eager_input_streaming: true`), 클라이언트 측 입력 검증. stop_reason이 tool_use(또는 pause_turn)인 동안 모든 tool_use를 로컬 도구로 실행하고 tool_result 목록을 한 user 메시지로 반환(실패는 is_error) |
| 스트리밍 | 별도 스레드 스트리밍을 큐로 전달하고, 소비자가 떠나면(Streamlit 재실행 등) 스트림을 취소해 연결을 닫음 |
| 시간 기준 | 연결·첫 스트림 이벤트 3.5초, 무이벤트 600초, SDK 재시도 `max_retries=0` |
| 프롬프트·이력 | 시스템 프롬프트는 세션 동안 바이트 단위 고정(권장 도구 순서, 숫자 규칙, 3구획 형식). 대화 이력은 추가만 함(append-only) |

대회 안내의 평가용 키 사용 한도는 코드가 아니라 키를 발급한 계정에서 설정하는 사항이며, 한도 초과 등으로 호출이 막히면 아래 폴백이 적용됩니다.

### 10.2 AI 활용 범위

- Claude(선택): 질문의 의도·지역·조건 해석(로컬 파서 결과를 힌트로 받고 틀리면 바로잡음), 도구 선택과 인자 결정, 한국어 해설 작성.
- 로컬 파이썬(두 경로 공통): 모든 수치 계산, 판정, 3단 대시보드, 증거 카드, 현장 확인 질문 선택. Claude가 호출하지 않은 도구는 로컬이 채웁니다(source=local-fill).
- 검증 장치: `number_auditor`가 해설 속 측정값(명, 분, 배, % 등)을 도구 결과·질문의 숫자와 대조해 "수치 근거 검증 X/Y 일치" 배지와 근거 없는 숫자 목록을 띄우고, `ensure_sections`가 빠진 구획만 덧붙이고 현장 확인 질문을 정확히 1개로 맞춥니다.
- AI 개발 도구: Anthropic Claude Code(코드·문서 작성 보조).
- 시험용 로컬 LLM: Ollama 0.34.2 의 gemma4:12b·qwen3:14b(Apache-2.0)가 견고성 시험용 변형 질문(`data/meta/robustness_variants_*.jsonl`, 각 2,548문항)과 대규모 조합 행동 시험의 자리표시자 문장틀(`data/meta/scale_frames_*.jsonl`, 호출 1,176회씩, 형식 검사 통과 gemma4 10,105개·qwen3 7,765개)을 만들었습니다. 생성 조건은 `data/meta/robustness_baseline.json` 과 `scripts/generate_question_frames.py` 머리말에 있고, 제출물 실행에는 쓰지 않습니다. 대규모 시험의 지명·시간·날씨 같은 끼울 값과 정답은 LLM 이 아니라 지명 사전과 코드(`scripts/scale_suite.py`)가 정합니다.
- 다양성 시험(결과 설명자료 7.11절): 같은 두 모델이 문장틀 57개를 말투 36종·상황(화자 12 x 경로 8 x 목적 9 x 감정 8)으로 다시 썼습니다(`data/meta/diverse_frames_gemma4.jsonl` 41,043문장, `diverse_frames_qwen3.jsonl` 41,038문장, 각 4,104회 호출). 끼울 값 2,057개(`data/meta/diverse_vocab.json`, source_type synthetic_seed)는 범주마다 Claude 에이전트 하나가 표현과 정답 필드를 제안하고 다른 에이전트가 독립 검토해 고른 합성 값이며, 정답 슬롯은 코드(`scripts/diverse_suite.py`)가 해석기와 따로 적은 어휘로 계산·교차 확인합니다. 해석기 결과를 보고 값을 빼거나 라벨을 바꾸지 않았습니다.
- 1억 문항 시험(결과 설명자료 7.12절): 새 LLM 문장틀은 만들지 않고 다양성 시험의 문장틀을 그대로 썼습니다. 새로 끼운 값 1,033개(`data/meta/mega_vocab.json`, source_type synthetic_seed)는 범주 둘씩 맡은 Claude 에이전트 5개가 기존 어휘와 겹치지 않게 범주마다 120개를 제안하고 다른 에이전트 5개가 라벨·모호성·숨은 조건·문장틀 적합성·중복을 독립 검토해 의심되는 표현 167개를 뺀 것입니다(에이전트는 해석기 코드와 시험 결과를 보지 않음). 절반(519개)은 평가용 전용이며, 정답 슬롯은 다양성 시험과 같은 규칙으로 코드가 계산합니다.
- 6천만 문항 시험(결과 설명자료 7.13절): 같은 두 모델을 데스크탑 GPU 의 Ollama 로 돌려 문장틀 57개를 새 말투 24종(이전 36종과 겹치지 않음)과 새 상황(화자 12 x 경로 8 x 목적 9 x 감정 8, 이전과 다른 요소)으로 새로 썼습니다(`data/meta/restyle_frames_gemma4.jsonl` 20,509문장, 2,052회 호출, 개발용 말투 12종 / `restyle_frames_qwen3.jsonl` 27,386문장, 2,736회 호출, 24종 모두). 다양성 시험과 같은 형식·뜻 검사를 통과하고 이전 시험 문장틀과 같지 않은 글만 쓰며(평가용은 개발용 틀과도 같지 않은 글만), 그 결과 개발용 17,303개·평가용 16,428개가 남습니다. 끼울 값과 정답은 1억 문항 시험과 같은 값 묶음과 규칙을 코드(`scripts/restyle_suite.py`)가 정하며, 해석기 결과를 보고 문장틀을 빼거나 라벨을 바꾸지 않았습니다.

### 10.3 외부 서비스 의존성과 자동 폴백

외부 서비스는 Anthropic Messages API 하나이며 선택입니다. API Key가 없거나 강제 로컬 스위치가 켜져 있으면 처음부터 로컬 엔진이 답하고 외부 호출은 0회입니다. Claude 경로에서는 401·403·404·400, anthropic 패키지 없음, 429, 그 밖의 상태 오류(5xx, 529 등), 네트워크 연결 실패, 첫 스트림 이벤트 3.5초 초과, 600초 무이벤트, 거절(stop_reason refusal), 출력 한도 도달(max_tokens), 빈 최종 응답과 그 밖의 예외가 생기면 화면 오류 없이 로컬 엔진으로 자동 전환합니다(이유 표기 15종, `REASON_LABELS`. 예: "API Key 인증 실패", "응답 지연(3.5초 내 첫 응답 없음)", "Claude 안전 정책상 응답 거절").

전환하면 상태창에 "(이유) -> 로컬 엔진 자동 전환"을 표시하고, 같은 질문·조건의 이전 Claude 해설이 캐시에 있으면 그 사실을 밝혀 보여 주며 없으면 로컬 엔진이 같은 4개 도구로 답합니다(캐시는 정상일 때 Claude 호출을 건너뛰는 데 쓰지 않음). 로컬 답변은 대화 이력에 덧붙여 다음 턴 문맥을 잇고, 화면 단계의 예외는 `data/processed/app_errors.log`에 기록한 뒤 강제 로컬로 다시 답합니다. 화면 배지는 키가 있으면 "하이브리드 부스터 모드 가동 중 (Anthropic Claude API 추론 + 로컬 정밀 연산 | 오프라인 자동 폴백 대기)", 없으면 "100% 로컬 온프레미스 자립 모드 가동 중 (외부 API 비용 0원 | 센터 PC 완벽 호환)" 문구입니다(원문에는 색 원 기호가 붙음).

실측: 최종 퍼징(`fuzz_report.json`)에서 401·닫힌 포트·첫 응답 지연·거절·529 다섯 장애 모두 로컬로 전환됐고 폴백 완료 시간은 143.7~3,647.3ms였습니다. 실제 키로 연결한 5문항은 2026-11-17·11-18 실행에서 모두 Claude 가 답했고, 그 전 실행에서는 SQL 주입 문자열 1건에 Claude 가 실제로 응답을 거절해 같은 방식으로 로컬 전환됐습니다(결과 설명자료 7.7절).
