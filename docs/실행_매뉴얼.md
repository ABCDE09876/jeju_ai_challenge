# 「제주의 두 얼굴」 실행 매뉴얼 (도민·심사위원용)

설치부터 화면 사용, 답변 해석, 문제 해결까지 순서대로 따라 할 수 있도록 정리한 사용 설명서입니다. Claude 사용 정책, 구조, 검증 결과, 제출 패키징은 프로젝트 루트의 `README.md` 에 있습니다.

> **먼저 알아 둘 점**
> - 현재 앱이 분석하는 데이터는 공식 예시데이터의 형식(컬럼명·코드값)을 그대로 따른 **시드 고정 합성(시연용) 데이터**입니다. 답변 끝에 같은 내용의 데이터 고지가 붙습니다. 화면의 결론을 실제 제주 현황으로 받아들이면 안 됩니다.
> - API Key 가 없어도 모든 기능이 동작합니다. 키를 넣으면 질문과 도구 결과 요약이 Anthropic API 로 전송되고 요금이 발생하므로, 질문에 개인정보를 넣지 마세요.

## 1. 설치

### 1-1. 필요한 것

| 항목 | 내용 |
|---|---|
| Python | 3.13 권장(검증 버전 3.13.9·3.12.10, Windows 11). 터미널에서 `python --version` (macOS·Linux 는 `python3 --version`)으로 확인합니다 |
| 인터넷 | 패키지 설치 때 필요합니다. API Key 없이 쓰면 앱 실행 중에는 외부로 나가는 요청이 없습니다 |
| 디스크 | 자동으로 만들어지는 DB 192,393,216바이트(약 183MiB) + 가상환경 |
| 프로젝트 폴더 | 제출 ZIP 을 푼 폴더. 아래 명령은 모두 이 폴더에서 실행합니다 |

### 1-2. Windows (PowerShell)

```powershell
cd "D:\경로\제주도AI만들기대회"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`Activate.ps1` 이 실행 정책 때문에 막히면 활성화하지 말고 다음처럼 설치합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 1-3. macOS / Linux

```bash
cd "/경로/제주도AI만들기대회"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 1-4. (선택) Claude API Key 넣기

두 방법 중 하나로 넣습니다. 둘 다 넣으면 화면 입력이 우선합니다.

1. **파일**: `.env.example` 을 `.env` 로 복사(Windows `Copy-Item .env.example .env`, macOS·Linux `cp .env.example .env`)하고 `ANTHROPIC_API_KEY=` 뒤에 키를 적습니다. 메모장에서 UTF-8 또는 ANSI(CP949)로 저장해도 읽힙니다.
2. **화면**: 앱 왼쪽 사이드바의 `Anthropic API Key (선택)` 칸에 붙여 넣습니다. 입력값은 가려서 표시되고, 파일로 저장되지 않으며, 이 브라우저 세션에서만 쓰입니다.

`ANTHROPIC_MODEL` 에 다른 모델을 적어도 무시됩니다. Claude 경로는 항상 `claude-opus-5-5`, effort `xhigh` 로 실행됩니다. `JEJU_DATAHUB_API_KEY` 는 앱 실행에 필요하지 않습니다.

## 2. 첫 실행과 종료

### 2-1. 실행 명령

| 상황 | Windows | macOS·Linux |
|---|---|---|
| 가상환경을 활성화한 경우 | `streamlit run src/app.py` | `streamlit run src/app.py` |
| 활성화하지 않은 경우 | `.\.venv\Scripts\python.exe -m streamlit run src/app.py` | `.venv/bin/python -m streamlit run src/app.py` |

- 브라우저가 자동으로 열립니다. 열리지 않으면 터미널에 표시된 Local URL(기본 `http://localhost:8501`)을 주소창에 입력합니다.
- Streamlit 을 처음 실행하면 터미널에 이메일 입력 안내가 나올 수 있습니다. 비워 두고 Enter 를 누르면 됩니다.

### 2-2. 처음 한 번 걸리는 준비 시간

- 화면에 `최초 실행 준비 중: 로컬 DB 확인·구축과 메모리 인덱스 적재(처음 한 번만, 약 10~40초)` 가 표시됩니다.
- 이때 로컬 DB `data/processed/jeju_truelife.db` 를 자동으로 만들고, 탭 3 시연용 표본 CSV 4개를 `data/samples/` 에 다시 씁니다. 검증 PC 의 DB 구축 기록은 6.8초입니다.
- 두 번째 실행부터는 DB 를 다시 만들지 않습니다.
- DB 를 만들지 못하면 원시 오류 대신 `python scripts/build_jeju_db.py` 실행을 안내하는 문구가 나옵니다(7장).

### 2-3. 종료

터미널에서 `Ctrl+C` 를 누릅니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.

| 상단 | 본문 맨 위 | 제목 `제주의 두 얼굴`, 소개 문장, 엔진 상태 배지, `현재 엔진:` 줄 |
| 탭 3개 | 본문 | 탭 1·2 는 대화형 분석, 탭 3 은 CSV 감사기 |

### 3-2. 상단 영역

- 제목 `제주의 두 얼굴` 과 소개 문장 `관광객·기상·평균의 3대 허수를 벗겨내는 도민 실생활 교차검증 및 시민 데이터 변호사 에이전트` 가 있습니다.
- 엔진 상태 배지는 둘 중 하나입니다.
  - API Key 가 있고 강제 오프라인이 꺼져 있을 때(보라색 배지):

    ```
    🟣 하이브리드 부스터 모드 가동 중 (Anthropic Claude API 추론 + 로컬 정밀 연산 | 오프라인 자동 폴백 대기)
    ```

  - API Key 가 없거나 강제 오프라인을 켰을 때(초록색 배지):

    ```
    🟢 100% 로컬 온프레미스 자립 모드 가동 중 (외부 API 비용 0원 | 센터 PC 완벽 호환)
    ```

- 배지 아래 `현재 엔진:` 줄에는 `API Key 미설정`, `강제 로컬 모드`, `claude-opus-5-5 · effort xhigh` 중 하나가 나옵니다.
- **주의**: 배지는 "키가 입력돼 있는가"만 보고 정해집니다. 키가 틀렸거나 네트워크가 막혀도 보라색 배지가 보일 수 있고, 그때는 질문마다 자동으로 로컬 엔진이 답합니다. 실제로 어느 엔진이 답했는지는 분석 진행 표시(3-6)와 실행 기록(3-9)에서 확인합니다.

### 3-3. 사이드바 `브레인 컨트롤러`

| 항목 | 화면 문구 | 하는 일 |
|---|---|---|
| API Key 칸 | `Anthropic API Key (선택)` (안내 문구 `비워 두어도 100% 로컬 모드로 작동합니다`) | 입력하면 `.env` 의 키보다 우선합니다. 가려서 표시되고 파일로 저장되지 않습니다 |
| 강제 오프라인 스위치 | `강제 로컬 오프라인 모드 테스트` | 켜면 키가 있어도 외부 호출 없이 로컬 엔진만 씁니다(두 모드 비교용) |
| 정책 안내 | `Claude 고정 정책: claude-opus-5-5 · effort=xhigh · adaptive thinking 고정`, `호출 횟수·토큰 상한 없음. 3.5초 무응답·오류·거절 시 로컬 엔진으로 자동 전환.` | 읽기 전용 안내입니다 |
| `Claude 연결 확인` | 버튼 | 짧은 실제 요청 1회로 키·네트워크 상태를 확인합니다(같은 고정 모델·effort 사용, 요금 발생). 성공하면 `연결됨 · (모델 이름) 응답 확인`, 실패하면 `연결 실패 · (사유)`. 키가 없거나 강제 오프라인이면 `강제 로컬 모드이거나 API Key 가 없어 확인을 건너뛰었습니다.` |
| `데이터 상태` | 표(source_type, tables, rows) | DB 에 든 데이터 종류별 테이블 수·행 수입니다(아래 표) |
| 스마트 캐시 | `스마트 캐시: N건 저장 · 재사용 M회` | 로컬 모드에서 같은 질문·조건의 결과를 저장·재사용한 현황입니다 |
| `대화 초기화` | 버튼 | 탭 1·2 의 대화 기록과 문맥 메모리를 모두 지웁니다. 탭 3 결과와 캐시는 그대로 둡니다 |

### 3-5. 원클릭 시연 시나리오 12개

버튼에 마우스를 올리면 실제로 보내지는 질문이 보이고, 누르면 그 질문이 바로 실행됩니다.

- 표의 "로컬 엔진 판정"은 문서 작성 시점에 새 대화에서 버튼 질문 하나만 로컬 엔진(캐시 미사용)으로 실행한 결과입니다(합성 데이터 기준).
- Claude 경로에서는 Claude 가 도구 조건을 정하므로 판정이 달라질 수 있습니다.
- 같은 탭에서는 앞 질문이 후속 질문으로 판단되면 그 조건을 이어받습니다. 표와 같은 결과를 보려면 먼저 사이드바의 `대화 초기화` 를 누릅니다.

### 3-6. 질문하기와 분석 진행 표시

1. 입력창에 질문을 쓰고 Enter 를 누르거나, 시나리오·후속 질문 버튼을 누릅니다.
2. 답변 위에 `에이전트 분석 중: Step 1 -> Step 4` 상자가 열리고 다음 줄이 차례로 나타납니다.

| 표시 예 | 뜻 |
|---|---|
| `의도·지명 해석(자모 퍼지 파서 + 문맥 추적) · 의도=profile, 지역=삼화지구, 주제=commute` | 로컬 파서가 읽은 의도·지역·주제(예시는 "삼화지구 퇴근 버스 어때?"). 오타를 고쳤으면 `지명 교정`, 앞 대화 조건을 이어받았으면 `이전 대화에서 이어받음: ...` 이 붙습니다 |
| `엔진: 로컬 신경-기호 엔진 · API Key 미설정` 또는 `엔진: Claude Opus 5.5 (effort xhigh) · claude-opus-5-5 · effort xhigh` | 이번 질문을 처리하는 엔진 |
| `Step 1 · 데이터셋·공간 키 결합 · 로컬 정밀 연산` (Claude 경로는 `· Claude 가 도구 호출`) | 도구 실행 시작. Step 1~4 가 차례로 나옵니다 |
| `완료: Step 1 · 데이터셋·공간 키 결합 (N ms · 판정 ... · local)` | 도구 실행 결과(소요 시간, 도구 판정, 실행 주체) |
| `Claude 추론 요약: ...` | Claude 경로에서만 나오며, 추론 요약이 갱신됩니다 |
| `엔진: 로컬 신경-기호 엔진 · (사유) -> 로컬 엔진 자동 전환` | Claude 를 쓸 수 없어 로컬 엔진으로 넘어갔다는 뜻입니다(예: `API Key 인증 실패 -> 로컬 엔진 자동 전환`) |
| `스마트 캐시 적중 · 같은 질문·조건의 로컬 결과 재사용` | 로컬 모드에서 같은 질문·조건을 다시 물었을 때 |

3. 분석이 끝나면 상자 제목이 `분석 완료 · (초) · (엔진 이름)` 으로 바뀌고 접힙니다. 답변 본문은 글자가 이어서 나오는 방식(스트리밍)으로 표시됩니다. Claude 답변이 나오는 중에 다른 버튼을 누르면 화면이 다시 그려지면서 진행 중이던 Claude 요청은 중단되므로, 답변이 끝난 뒤 다음 조작을 합니다.

### 3-11. 탭 3: CSV 실시간 감사기

CSV 와 주장 문장을 넣으면 인코딩을 자동 복구한 뒤 (1) 주장 속 수치 재계산 (2) 월 경계의 계단식 집계 단절 탐지 (3) 컬럼 스키마 대조로 인과 과장 교정을 한 번에 수행합니다. 공식 예시데이터 70개 시트와 컬럼을 대조해 어떤 공식 데이터와 닮았는지도 알려 줍니다.

1. 왼쪽 `CSV 파일 끌어 놓기(UTF-8, CP949, EUC-KR, 탭·세미콜론·파이프 구분 모두 가능)` 칸에 파일을 끌어 놓거나(확장자 csv, txt, tsv), `또는 내장 표본으로 시연` 에서 표본을 고릅니다. 둘 다 고르면 올린 파일이 우선합니다.
2. 오른쪽 `검증할 주장 문장(선택)` 에 주장을 씁니다. 표본을 고르면 기본 주장이 채워집니다.
3. `감사 실행` 을 누릅니다.
4. 결과: 판정 배지와 굵은 한 줄 요약 -> 3열(수치 사실 / 역전 구간과 `월별 재계산(점선: 계단식 점프)` 그래프 / 한계·현장 확인 질문·중립 교정문·증거 카드 버튼) -> `복구 내역·스키마 대조·재계산 상세` 펼침 상자(인코딩, 구분자, 행·열 수, 복구 내역, 공식 시트 대조, 월 경계, 점프 등).

| 배지 | 내부 값 | 한 줄 요약 |

| 집계 단절 | `structural_break` | 월 경계에서 계단식 집계 단절이 보여, 이 변화를 실제 증감으로 단정할 수 없습니다. |

## 4. 답변 읽는 법

### 4-1. 답변의 뼈대

모든 답변은 같은 순서로 나옵니다.

```
결론: 1~2문장
[원자료로 확인된 수치 사실]
- 도구가 DB 에서 직접 계산한 핵심 수치
[교란 제거 후 역전 구간]
- 교란을 걷어냈을 때 뒤집히거나 드러나는 구간, 결론이 바뀌는 경계 시각, 또는 '역전 없음'
[원자료 컬럼 부재로 인해 단정할 수 없는 한계 및 현장 확인 질문 1개]
- 한계: 이 데이터로 알 수 없는 부분
- 현장 확인 질문: (정확히 1개)
데이터: 공식 예시데이터 스키마를 보존한 시드 고정 합성(시연용) 데이터 기준이며, data/raw 에 원자료를 넣으면 같은 절차로 재계산됩니다.
```

| 구획 | 읽는 법 |
|---|---|
| 결론 | 판정 배지와 같은 내용을 한두 문장으로 요약합니다. 배지를 먼저 보고 결론을 읽습니다 |
| `[원자료로 확인된 수치 사실]` | 도구가 DB 에서 계산한 값만 있습니다. 예: `삼화지구 도외 거주자(관광객) 체류 비중: 2.7%`. 지명을 자동으로 고쳤다면 맨 위에 `지명 자동 교정: ...` 이 붙습니다 |
| `[교란 제거 후 역전 구간]` | 관광객 제거 -> 생활 시간대 -> 악천후 순으로 한 겹씩 벗겼을 때 1위가 바뀌는지, 결론이 뒤집히는 시각(경계), 평균에 가려진 과부하 조각, 집계 단절을 보여 줍니다. `순위 유지` 나 `경계 없음` 도 의미 있는 결과입니다 |
| `[원자료 컬럼 부재로 인해 단정할 수 없는 한계 및 현장 확인 질문 1개]` | 이 데이터로 알 수 없는 것과, 표본이 적어 조건을 넓혔다면 그 사실이 나옵니다. 마지막 현장 확인 질문 하나는 데이터 밖에서 직접 확인해야 할 내용입니다 |
| 데이터 고지 | 합성 데이터 기준인지 원자료 기준인지 알려 줍니다. 답변에 쓰인 테이블이 모두 원자료일 때만 `원자료(official_raw) 기준` 으로 바뀝니다 |

주장 검증 답변에는 `중립 교정문` 이 붙기도 합니다. 원인을 단정한 문장을 데이터로 확인된 범위로 고쳐 쓴 문장입니다. 예(`집계 단절` 시나리오): `한림읍의 음식물쓰레기 배출량이 변했다(원인 미확인, 관광객 영향은 추가 자료로 검증 필요).`

### 4-2. 판정 배지의 뜻

| 배지 | 내부 값 | 뜻 |
|---|---|---|
| 순위 역전 | `reversal` | 단순 평균의 1위와 교란을 걷어낸 뒤의 1위가 다릅니다 |
| 조건부 역전 | `conditional_reversal` | 평상시 결론은 유지되지만 비 오는 날 같은 스트레스 조건에서는 1위가 뒤집힙니다 |
| 역전 없음 | `no_reversal` | 교란을 걷어내도 순위가 유지됩니다 |
| 평균에 가려진 과부하 | `masked_overload` | 평균은 평범하지만 특정 요일·시간대·날씨/장날 조각에서 붐빕니다 |
| 집계 단절 | `structural_break` | 월초 계단식 점프가 있어 집계·수집 방식 변경이 의심되므로 실제 증감으로 단정할 수 없습니다 |
| 미측정 인과 | `unmeasured_cause` | 수치 변화는 확인되지만 주장한 원인을 측정한 컬럼이 없습니다 |
| 분모 함정 | `thin_denominator` | 평균이 전체 중 일부 행으로만 계산돼 대표값으로 쓸 수 없습니다 |
| 정상 주장 확인 | `confirmed` | 주장이 데이터와 일치합니다 |
| 주장과 반대 | `refuted` | 주장이 관광객이 섞인 단순 평균으로만 맞고, 도민 기준으로는 반대입니다 |
| 역전 경계 있음 | `boundary` | 귀가·방문 시각 같은 조건을 움직이면 결론이 뒤집히는 지점이 있습니다 |
| 경계 없음 | `no_boundary` | 검토한 범위 전체에서 같은 결론입니다 |
| 판정 보류 | `abstain` | 필요한 컬럼이나 기간이 없어 억지로 판정하지 않고 현장 확인 질문을 드립니다 |
| 판정 유보 | `inconclusive` | 확보한 근거로는 어느 쪽으로도 단정하기 어렵습니다. 두 지역 차이가 3% 미만이거나, 주장한 조건의 효과가 원자료에서 확인되지 않거나, 판정 도구가 결과를 내지 못한 경우(결론에 실패한 단계 이름 표시)입니다 |
| 연관만 확인 | `correlation_only` | 원인 후보 컬럼은 있으나 인과는 단정할 수 없습니다 |
| 과부하 없음 | `none` | 평균에 가려진 과부하 조각이 없습니다 |
| 안내 | `info` | 사용법·데이터 안내입니다 |
| 지역 미지정 | `insufficient_area` | 제주 지역명을 찾지 못했습니다. 동네 이름(예: 노형동, 신제주, 삼화지구)을 함께 적어 주세요 |
| 수치 불일치 / 이상 없음 / 판독 불가 | `figure_mismatch` / `no_issue` / `unreadable` | 탭 3 CSV 감사 전용 판정(3-11) |

### 4-3. 수치 근거 검증 배지

오른쪽 열의 `수치 근거 검증 X/Y 일치` 배지는 해설 문장 속 숫자 Y개 가운데 X개가 도구 결과(또는 질문)에서 확인됐다는 뜻입니다.

- 모두 확인되면 초록색, 하나라도 못 찾으면 빨간색이며 `도구 결과에서 찾지 못한 수치: ...` 로 해당 숫자를 보여 줍니다.
- 예: `관광객 거품` 시나리오는 `25/25 일치` 였습니다(작성 시점 로컬 실행).
- 이 검사는 보조 장치입니다. 날짜(년·월·일) 숫자, 18시 같은 정수 시각, 곳·회·개 같은 개수 단위가 붙은 정수, 소수점 없는 0·1·2·3 은 검사하지 않고 반올림 오차를 허용합니다. 분·명·배·% 값은 검사합니다. 초록 배지가 해석의 옳음을 보장하지는 않습니다.

### 4-4. 조건 완화·판정 보류·지역 미지정

- **조건 완화**: 요청 조건의 표본이 5건(일) 미만이면 "요청 조건 -> 인접 시간대·평일/주말 구간 -> 해당 지역 전체 기간·전체 시간" 순으로 넓히고, 한계 구획에 `요청하신 세부 조건(N=...)의 표본이 적어 ... 기준으로 자동 확장해 분석했습니다.` 형태의 문장을 적습니다. 이 문장이 보이면 결과를 요청 조건 그대로의 값으로 읽지 마세요.
- **판정 보류**: 부동산 가격(집값·월세·전세 등), 소음, 치안·범죄, 학군·교육 평판, 대기질, 주차 수요, 주관적 만족도처럼 원자료에 컬럼이 없는 개념이나 보유 기간 밖 시점(예: "작년 겨울")을 물으면 판정을 보류하고 확인 방법을 안내합니다.
- **지역 미지정**: 제주 지역명이 없거나 제주 밖 지역(예: 서울 강남역)을 물으면 동네 이름을 함께 적어 달라고 안내합니다.

### 4-5. Claude 답변의 형식 보완 표시

Claude 해설에 세 구획이나 현장 확인 질문이 빠지면, 로컬 엔진이 같은 도구 결과로 빠진 부분만 덧붙이고 `형식 보완: 빠진 근거 구획만 로컬 엔진이 같은 도구 결과로 덧붙였습니다.` 라고 표시합니다. 현장 확인 질문이 여러 개 나오면 첫 번째 하나만 남깁니다.

### 4-6. 주장 문장을 쓸 때

- 비교 주장은 "애월이 아라동보다 활기차다"와 "아라동보다 애월이 활기차다" 어느 어순이든 '보다' 바로 앞 지역(아라동)을 비교 대상으로 읽습니다. '비교적', '덜', '적지 않다'·'많지 않다' 같은 표현도 방향을 반영합니다.
- 탭 3 에서 "2020년 10월에 9월보다 0.7배로 줄었다"처럼 쓰면 앞에 나온 달을 뒤에 나온 달로 나눈 비율(10월 / 9월)로 다시 계산합니다. 감소는 1 보다 작은 값으로 나옵니다.

## 5. 멀티턴 대화 예시

같은 탭에서 이어서 물으면 앞 질문의 지역·주제·시간대·날씨 등을 이어받습니다. 아래는 문서 작성 시점에 탭 1 에서 로컬 엔진(캐시 미사용)으로 실제 실행한 5턴 대화입니다(합성 데이터 기준).

| 차례 | 입력 | 이어받은 조건(화면 표시) | 판정 | 결론 |
|---|---|---|---|---|
| 1 | 삼화지구로 이사 가면 퇴근 버스 괜찮을까? 아라동이랑 비교해 줘 (`이사·귀가 경계` 버튼) | 없음 | 역전 없음 | 교란을 걷어내도 '아라동'이 계속 앞섭니다. 다만 결론 역전 경계: 20시. 그 전에는 '삼화지구', 그 이후에는 '아라동'이 귀가에 유리합니다. |
| 2 | 그럼 퇴근 시간을 8시 이후로 바꾸면? | 지역, 의도 | 역전 경계 있음 | 요청하신 20시 기준으로는 '아라동'이 유리합니다. 결론 역전 경계: 20시. |
| 3 | 비 안 올 때는? | 지역, 주제, 시간대, 의도 | 역전 경계 있음 | 2번과 같은 결론을 비 안 오는 날 조건으로 다시 계산 |
| 4 | 거기 말고 노형동이랑 비교해 줘 | 기준 지역, 주제, 시간대, 날씨, 의도 | 경계 없음 | 검토한 17~23시 전 구간에서 '노형동'이 계속 유리합니다(경계 없음). (비교 지역: 삼화지구, 노형동) |
| 5 | 주말엔? | 지역, 주제, 시간대, 날씨, 의도 | 경계 없음 | 같은 결론을 주말 조건으로 다시 계산 |

읽는 요령:

- 2번의 "퇴근 시간을 8시 이후로"는 "퇴근"이라는 단서 덕분에 20시로 해석됐습니다. 조건이 바뀌면 수치 사실도 다시 계산됩니다. 예를 들어 삼화지구 귀가 불편 지수(대기+혼잡, 분)는 2번(날씨 전체)에서 `17시 4.1분, 20시 8.0분, 23시 33.5분`, 3번(비 안 올 때)에서 `17시 3.5분, 20시 7.8분, 23시 33.2분` 이었습니다.
- 4번의 "거기 말고"는 비교 상대(아라동)를 노형동으로 바꾸고 기준 지역(삼화지구)은 유지했습니다.
- 이어받은 조건은 분석 진행 표시의 `이전 대화에서 이어받음: ...` 과 답변 안의 `이전 대화에서 이어받은 조건: ...` 줄에 나옵니다.
- **주의**: 오전·저녁 단서 없는 "8시"는 질문 주제(앞 대화에서 이어받은 주제 포함)를 따릅니다. 퇴근·야간·생활 주제면 20시(이 시나리오에서 "그럼 8시 이후는?"은 20~23시), 장날 혼잡·소비 같은 그 밖의 주제면 오전 8시입니다. 헷갈리지 않게 "저녁 8시 이후"처럼 적어 주세요.
- 새 주제로 넘어갈 때는 사이드바의 `대화 초기화` 를 누르면 이전 조건이 섞이지 않습니다.

## 6. 심사위원용: 두 모드 비교하기

1. API Key 를 넣습니다(`.env` 또는 사이드바). 상단에 보라색 하이브리드 배지가 보입니다. 필요하면 `Claude 연결 확인` 으로 연결을 확인합니다(요금 발생).
2. 시나리오 버튼 하나(예: `우천 은폐 혼잡`)를 누릅니다. 분석 진행 표시에 `엔진: Claude Opus 5.5 (effort xhigh)` 와 `Claude 가 도구 호출` 이 나오고, 중간에 `Claude 추론 요약` 이 갱신됩니다.
3. 사이드바의 `강제 로컬 오프라인 모드 테스트` 를 켭니다. 배지가 초록색으로 바뀝니다. `대화 초기화` 를 누른 뒤 같은 버튼을 다시 누릅니다.
4. 비교할 점:
   - 판정 배지와 수치 사실: 두 경로가 같은 도구 함수를 쓰므로 같은 조건이면 수치가 같습니다. Claude 가 시간대 같은 조건을 다르게 해석하면 수치가 달라질 수 있습니다.
   - 해설 문장: Claude 경로는 Claude 가 쓴 문장, 로컬 경로는 템플릿 문장입니다.
   - 소요 시간: 로컬 엔진은 벤치마크 기록상 문항당 평균 270.7ms(held-out v1)이고, Claude 경로는 실제 연결 40문항에서 중앙값 36.0초, p95 58.9초, 최대 65.3초였습니다(2026-11-19, `live_report_v1.json`. 5문항 시험은 10.6~46.1초, `README.md` 4장, 9-10).
   - 실행 기록의 `source` 열: `claude`, `local-fill`, `local` 구분.
5. 장애 전환 시연: 강제 오프라인을 끄고 사이드바 키 칸에 일부러 틀린 키를 넣은 뒤 질문합니다. 분석 진행 표시에 `API Key 인증 실패 -> 로컬 엔진 자동 전환` 이 나오고 같은 형식의 답이 나옵니다. 퍼징 기록상 이 경우 질문 시작부터 로컬 답변 완료까지 522.8ms 였습니다.
6. 키 없이 시연: 키 칸을 비우고 `.env` 에도 키가 없으면 초록색 로컬 배지로 모든 탭이 동작합니다.

## 7. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 브라우저가 열리지 않음 | 자동 열기가 막힘 | 터미널의 Local URL(기본 `http://localhost:8501`)을 주소창에 입력합니다 |
| 포트가 이미 사용 중이라는 오류, 또는 엉뚱한 화면이 열림 | 다른 Streamlit 앱이나 프로그램이 같은 포트를 사용 | 이전에 띄운 앱을 그 터미널에서 `Ctrl+C` 로 끄거나, `streamlit run src/app.py --server.port 8502` 처럼 다른 번호로 실행한 뒤 터미널에 표시된 주소로 접속합니다 |
| `ModuleNotFoundError: No module named 'streamlit'` 등 패키지 누락 | 가상환경이 활성화되지 않았거나 설치가 끝나지 않음 | 가상환경을 활성화하고 `python -m pip install -r requirements.txt` 를 다시 실행합니다. 활성화 없이 `.\.venv\Scripts\python.exe -m streamlit run src/app.py` 로 실행해도 됩니다 |
| PowerShell 에서 `streamlit` 명령을 찾을 수 없음 | PATH 에 streamlit 이 없음 | `python -m streamlit run src/app.py` 로 실행합니다 |

## 8. 알려진 제약

1. **합성 데이터**: 결론은 실제 제주 현황이 아니라 분석 절차 시연입니다. 원자료를 넣는 경로는 실데이터로 끝까지 검증하지 않았습니다.
2. **보유 기간**: 생활 주제(유동인구·버스·날씨)는 2026-05-01 ~ 2026-10-31 합성 기간만 있습니다. 주제별로 카드 2025-11 ~ 2026-10, 음식물쓰레기 2018-01 ~ 2021-05, 와이파이 2019-01 ~ 2021-12 입니다. 기간 밖 시점은 판정 보류합니다.
3. **측정하지 않는 것**: 부동산 가격, 소음, 치안·범죄, 학군, 대기질, 주차, 주관적 만족도는 판정 보류합니다. 강수량은 일 단위라 특정 시각의 비 여부를 모르고, 시간대별 배차는 합성값이며, 차내 혼잡·배차 지연은 없습니다.
4. **지역**: 제주 43개 읍면동과 생활권 별칭(신제주, 구제주, 삼화지구 등)만 인식합니다. 영어만 쓴 질문은 지명을 찾지 못할 수 있습니다(퍼징 기록: `Compare Nohyeong and Ara for commuting` 은 지역 미지정으로 답함).
5. **시각 해석**: 오전·저녁 단서 없는 "8시"는 퇴근·야간·생활 주제면 20시, 그 밖의 주제면 오전 8시로 해석됩니다(5장). "밤 열 시", "10pm" 처럼 쓴 시각도 읽습니다.
5-1. **말투와 오타**: 반말·제주어·어르신 말투·영어 단어 섞기는 대부분 같은 뜻으로 해석하지만(`README.md` 9-5), 문장 전체를 영어로 쓰거나 '언제'·'주말' 같은 핵심 단어 자체를 틀리게 쓰면('엉제', '쥬말') 다르게 해석될 수 있습니다. 분석 진행 표시의 `의도·지명 해석` 줄에서 지역·주제·조건이 맞는지 확인합니다.
6. **벤치마크 미탐 유형**: 주말 전체의 감소와 상쇄된 토요일 혼잡(동문로터리 정류소)을 찾지 못한 문항(T10)이 있습니다.
7. **Claude 경로**: 응답에 10초 이상 걸릴 수 있고(실제 연결 40문항 중앙값 36.0초, 최대 65.3초), 비용 상한이 없으며, 인터넷이 필요하고, 질문 내용이 외부로 전송됩니다. 답변이 나오는 중에 다른 버튼을 누르거나 질문을 보내면 화면이 다시 그려지면서 진행 중이던 Claude 요청은 중단됩니다. 상단 배지는 키 유무만 보고 정해집니다.
8. **수치 근거 검증 배지**: 보조 장치이며 해석의 옳음을 보장하지 않습니다(4-3).
9. **시연용 단일 사용자 앱**: 로그인·접근 제어가 없고, 대화 기록은 새로고침하면 사라집니다.
10. **검증 환경**: Windows 11 + Python 3.13.9(개발 PC)와 3.12.10(별도 PC, 새 가상환경에 `requirements.txt` 만 설치)에서만 실행 검증했습니다. 센터 PC 실기, macOS, Linux 실행 기록은 없습니다.
